## 一、HarmonyOS 应用签名（血泪篇）

### 1.1 两种签名方式

| 方式 | 用途 | 说明 |
|------|------|------|
| **自动签名**（DevEco UI） | 真机调试 | `File → Project Structure → Signing Configs` 登录华为账号勾选自动生成；材料在 `C:\Users\<user>\.ohos\config\openharmony\` |
| **手动签名**（上架必用） | 发布上架 | 密钥库 .p12 + CSR → AGC 申请发布证书 .cer → 创建 Profile .p7b → DevEco UI 配置 |

### 1.2 关键教训

1. **CSR 必须用 DevEco 的 `Build → Generate Key and CSR` 生成**（或 keytool 加 `-sigalg SHA256withRSA`）。命令行 keytool 默认签名算法是 **SHA384withRSA**，AGC 上传报"CSR 文件无效"——重新生成时显式指定 `-sigalg SHA256withRSA` 即可（`-printcertreq` 可验证）。
2. **hvigor 的 signingConfigs 密码不是明文**：`storePassword/keyPassword` 必须是 DevEco 用 `material/` 目录材料加密后的 **hex 密文**（AES-128-GCM）。手动往 build-profile.json5 写明文密码必然失败（报"密码长度 <32"或"keystore password was incorrect"）。**必须通过 DevEco UI 配置签名**，让 IDE 生成密文 + material 目录。
3. **`material/` 目录不能删**：它是解密签名配置的钥匙（`fd/`+`ac/`+`ce/` 三部分合成密钥），删了签名立即失败。它和 .p12/.cer/.p7b 一起构成签名凭据，**整个 signing 目录必须备份**。
4. **签名算法 signAlg 枚举**：schema 只允许 `SHA256withECDSA`（写 SHA384withECDSA 会报 00303038 Configuration Error）。
5. **证书类型**：上架必须选**发布证书**（每账号限 1 个发布证书 + 2 个调试证书）；调试证书不能上架。
6. **密钥库密码**：DevEco UI 部分版本不让输入 `!` 等特殊字符——选密码时避开被禁字符（如 `Lingxi@2026Flow`）。
7. **证书/Profile 与密码无关**：改 p12 密码不影响已签发的 .cer/.p7b（`keytool -storepasswd` 改库密码；PKCS12 无独立 keypass）。

### 1.3 打包与验证命令

```bash
# 环境变量
set DEVECO_SDK_HOME=C:\Huawei\DevEco Studio\sdk
set JAVA_HOME=C:\Huawei\DevEco Studio\jbr

# HAP（复赛提交/侧载）
hvigorw assembleHap --mode module -p product=default --no-daemon

# APP Pack（上架用！注意：不能带 --mode module）
hvigorw assembleApp --no-daemon

# 验证签名
java -jar "%DEVECO_SDK_HOME%\default\openharmony\toolchains\lib\hap-sign-tool.jar" ^
  verify-app -inFile xxx-signed.app -outCertChain out.cer -outProfile out.p7b
# 输出 "Digest verify result: true" 即签名有效
```

- 产物位置：HAP → `entry/build/default/outputs/default/`；APP → `build/outputs/default/`
- **HAP/APP 无 META-INF 是正常的**：新版签名用 zip 尾部签名块（Signing Block v2/v3），用 hap-sign-tool 验证而非看 zip 内容

### 1.4 版本号管理（重要）

- **包内版本**（`AppScope/app.json5`）：`versionName` 上架从 `1.0.0` 起，`versionCode` 数字递增（1000000 → 1000001…）
- **开发迭代号**（docs 内 v0.4→v1.2）：仅内部记录，**不要**与上架版本混用
- 出包命名规范：`灵犀流序_<versionName>_上架版.app` / `_签名版.hap`

## 二、AGI 审核资料经验

1. **分类/标签**：AI 助手类选**效率**分类；主标签选 **AI**（搜索流量大），副标签覆盖功能关键词
2. **一句话简介 ≤17 字**：突出"AI"关键词提升曝光，如"AI 助理，一句话完成你的任务"
3. **隐私权限理由**：每个 user_grant 权限按"用途 + 触发时机"写清（如"语音输入：您说话后本机转文字再发送给 AI"），避免含糊
4. **隐私政策**：用华为「协议服务」模板生成最稳；AI 生成式应用必须加"AI 生成内容声明"（内容由大模型生成仅供参考）
5. **APP 备案**：个人开发者走华为 AGC 一站式备案通道，**提前 1-2 周办理**（审核可能卡在这）
6. **AI 功能声明**：有 AI 对话就要勾选"AI 生成合成服务"（文本生成）
7. **截图**：手机竖屏截图不能直接传（要求 16:9），用**横屏模拟器**截图或竖屏图合成 16:9 画布
8. **上架资料与产品能力一致**：未申请的能力（如实况窗）不要在资料中宣称

## 三、代码/UI 经验

1. **主页标题 `_flow` 看不清**：文字用了 `accent` 色，而标题区背景恰好是 `gradientEnd→accent` 渐变——**文字与背景同色系**。文字色避免与所在区域背景渐变同色系，渐变顶部用 `textOnPrimary`（白）最稳
2. **对比度用公式验证**：WCAG 相对亮度公式（0.2126R+0.7152G+0.0722B 线性化）——正文 ≥4.5:1、图标/标题 ≥3:1，加新颜色先算再改（浅色主题辅助色 `#94A3B8` 只有 2.4:1，审核必挂）
3. **语义色也是文字色（二轮驳回教训）**：警示/成功/危险色（琥珀 `#F59E0B`、绿 `#10B981`、红 `#EF4444`）用于提示文字/状态标识时同样要过 4.5:1——审核第一轮只查主题 token 漏了这些，第二轮全被驳。修复：琥珀→`#92400E`、绿→`#047857`、红→`#DC2626`
4. **标题压在渐变上**：主页 "Lingxi" 深色字 on 紫色渐变只有 2.3:1——渐变顶部一律用白字（`textOnPrimary`），并微调深色渐变端色保证白字 >3:1
5. **导航条融合**：非沉浸式应用也要设置 `setWindowBackgroundColor` 跟随主题，否则底部导航条区域颜色突兀
6. **hvigor 任务参数**：`assembleHap` 需要 `--mode module`；`assembleApp` **不能**带（工程级任务，带了报"Task was not found"）
7. **资源引用**：改颜色一律走 `ThemeService` Token，不要散落硬编码色值（对比度修正一处生效全局）

## 2026-08-08 模拟器网络栈缓冲 SSE 流式响应（最贵的排查教训）

**现象**：所有模型商、所有版本（含 8月4日旧包）、所有请求形态都"慢"——流式请求 185 秒无首字节、15 分钟才完成；但非流式请求**几秒完成**（模型思考+工具+输出全算上）。

**真相**：HarmonyOS 模拟器（Windows x86_64）网络栈对 chunked/SSE 流式响应存在缓冲——数据实际已到达，但网络栈不派发给应用层，应用层看起来"无数据"。物理网络完全正常（NETSTACK：RTT 11ms、零重传、连接 39ms、服务端 200）。

**判定方法**：
1. NETSTACK 日志（Log 面板搜 netstack）——物理层正常但 starttransfer_time 巨大 = 客户端网络栈问题
2. 换非流式（stream:false）测试——立竿见影 = 流式路径问题
3. 对照实验：PC 上 curl 秒回 + 模拟器里慢 = 模拟器问题

**解决方案（已落地）**：
- ApiSettingsPage「兼容模式（非流式）」手动开关
- 自动降级：流式 30 秒无首字节 → 自动销毁并重试非流式（AgentCore 识别"首字节"错误）
- watchdog 300s + 降级重试（180s 旧值会在 185s 首字节前 5 秒误杀）

**教训**：排查"慢"问题时，先做**非流式对照**——30 秒内区分客户端网络栈问题与服务端问题，不要先怀疑代码/模型/服务商。

## 2026-08-08 设计决策：默认锁定非流式（兼容模式）

**决策**：灵犀默认使用非流式响应（stream:false），用户可在 API 设置中开启流式。

**理由**：
1. 灵犀定位为轻型个人助理——单轮任务（提醒/天气/文件/技能）端到端几秒完成，流式打字效果没有实际价值
2. 模拟器及部分网络栈对 SSE/chunked 有缓冲问题（见上文），流式引入额外风险
3. 非流式路径代码更简单（无 SSE 解析、无 watchdog 竞态、无节流渲染），出错面小

**保留**：流式实现完整保留（真机打字机体验），自动降级逻辑（30s 首字节停滞 → 非流式）作为流式模式的兜底。
